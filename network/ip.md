# ip

## 공인/사설 ip

- 공인
    - 인터넷 전체에서 유일한 주소
    - 가정에서는 보통 통신사가 공유기(라우터) 바깥 포트에 공인 IP 1개를 할당
- 사설
    - 해당 네트워크 내에서만 유일하게 사용되는 주소
    - 외부(인터넷)으로 나갈 때는 NAT 통해 공인 IP 로 변환
    - 10.0.0.0/8 (10.0.0.0 ~ 10.255.255.255)
    - 172.16.0.0/12 (172.16.0.0 ~ 172.31.255.255)
    - 192.168.0.0/16 (192.168.0.0 ~ 192.168.255.255)

## class

- IPv4 앞 몇 비트에 따라 네트워크를 나누는 규칙
    - 현재는 CIDR 로 대체되어 사용되지 않음
- A class: 0~127 (/8)
    - 네트워크 수: 128개
    - 호스트 수: 16,777,214
- B class: 128~191 (/16)
    - 네트워크 수: 16,384
    - 호스트 수: 65,534
- C class: 192~223 (/24)
    - 네트워크 수: 2,097,152
    - 호스트 수: 254
- D, E ...
- ip 주소만으로 네트워크 영역을 알 수 있도록 하기 위함
- 네트워크 영역은 아래 두 목적으로 필요
    - 목적지가 출발지와 같은 네트워크면 직접 보내고, 아니면 게이트웨이(공유기)로 보냄
    - 네트워크 영역을 기준으로 라우팅 테이블 항목(경로) 수 최소화 (150.10.0.0/16 -> A대학, 150.20.0.0/16 -> B대학)
- 주소 고갈 이슈
    - B class 기준 네트워크 영역은 128~191(/16) 이므로 16,384개
    - B class 기준 16,384 개 조직들이 사용하면 고갈
    - C class 는 네트워크 영역의 수가 209만으로 많지만 호스트 영역의 크기가 256 개로 적음
- 주소 낭비 이슈
    - B class 기준 호스트 영역으로 사용가능한 부분은 65,536개
    - 해당 ip를 할당받은 조직이 2000개 정도 호스트 ip를 사용한다고해도 나머지 ip를 다른 조직에 줄 수 없었음
    - `150.10` 이라는 B class IP를 할당받은 경우 라우팅 테이블에서 `150.10` 은 전부 해당 조직으로 보내기 때문
    - 클래스로만 분류되어 `150.10.100` 까지 봐야하는 경우도 있다는 것을 표현할 방법이 없었음

## 서브넷팅

- 건물이 여러 개인 회사가 클래스 네트워크를 하나 받았을 때, 건물마다 LAN이 하나 씩 필요
- 클래스만 있다면 클래스 번호가 건물수 (LAN 수) 만큼 필요할 것이고, 이렇게 되면 인터넷 라우팅 테이블이 폭발적으로 커지고 클래스 번호도 소모됨
    - 번호를 1개만 쓰고 별도 브리지 같은 네트워크 장비로 LAN 을 묶는 방법도 가능하지만 결과적으로 LAN이 커질수록 브로드캐스트 비용과 브리지 관리 등 부담 생김
- 클래스 번호는 한 개만 받고 호스트 영역을 서브넷으로 나눈다.

```
클래스 : [ 네트워크 ][      호스트        ]
서브넷팅: [ 네트워크 ][ 서브넷 ][   호스트   ]
```

- B class 150.10.x.x 를 받은 회사에서 3개 건물이 있는 경우
    - A 건물 서브넷: 150.10.1.0 (150.10.1.0 ~ 150.10.1.255)
    - B 건물 서브넷: 150.10.2.0 (150.10.2.0 ~ 150.10.2.255)
    - C 건물 서브넷: 150.10.3.0 (150.10.3.0 ~ 150.10.3.255)
- 클래스 구분만으로는 서브넷 식별이 불가능하여 서브넷마스크 개념 도입
    - 서브넷마스크: 네트워크 + 서브넷 영역을 1로 호스트 영역을 0으로 표시한 32비트 값
    - 위 예시의 경우 서브넷 마스크는 255.255.255.0

## CIDR

- CIDR (Classless Inter-Domain Routing)
- 클래스 구분없이 `/숫자` 로 네트워크 영역 길이를 직접 명시하여 주소를 할당하고 라우팅하는 방식
- 등장 이유
    - 수백~수천명 중간 규모 조직에 맞는 크기가 없어서 생긴 B 클래스 고갈 이슈
    - 인터넷 라우팅 테이블 항목(경로) 수의 폭발적 증가 (B 클래스 못받은 조직이 C를 여러개 받는 경우가 빈번. 조직 1개가 라우팅 테이블 상 여러 개를 차지)
- 표기
    - `주소/숫자`
    - 숫자 크기만큼 네트워크 영역
    - 서브넷마스크와 같음 (/24 == 255.255.255.0)
- 계층적 할당
    - IANA (전셰계 IP 괸리)에서 RIR(지역 레지스트리 5곳)으로 /8단위 할당
    - RIR 에서 통신사(ISP) 로 /15, /21 등 할당
    - ISP 로부터 고객이 /24 할당
    - 고객은 내부적으로 서브넷 직접 분할
- 이제 클래스 단위가 아닌 보다 적절한 크기의 호스트 영역을 가진 주소를 할당 가능
    - 적절한 크기를 할당할 수 있으므로 B클래스 고갈 이슈 해결하고, C클래스를 여러 개 할당받는 이슈도 해결
- 경로 집약을 통해 라우팅 테이블 항목 수 감소
    - 고객은 ISP의 블록 일부를 할당, ISP의 큰 블록 전체 하나만 라우팅 테이블에 광고 (고객 별 ip를 광고할 필요없음)
